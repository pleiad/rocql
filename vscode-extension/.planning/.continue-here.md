## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Voseo / argentinismos en respuestas | Caí en voseo durante toda la sesión a pesar de que ~/.claude/CLAUDE.md lo prohíbe. El usuario tuvo que recordármelo. | advisory | Memory file `feedback_no_voseo.md` agregado al sistema de memorias del usuario. Verificar antes de responder. |
| `network.moveNode` sobre nodos ocultos | vis-network falla silenciosamente si el nodo no está en el dataset actual. Lo descubrí cuando `arrangeByFile` parecía no aplicarse a nodos filtrados. | advisory | `arrangeByFile` solo escribe a `positionCache`; `applyFilters` aplica las posiciones vía `setData` con `x, y`. |
| `setData` durante stabilization inicial | Mensajes asincrónicos de `cursorScope` llamaban `applyFilters` → `setData` mientras la primera estabilización de barnesHut corría, reiniciándola y dejando los nodos en posiciones a medias ("bola"). | blocking | Flag `ready` en el webview: `applyFilters` retorna temprano hasta que `stabilizationIterationsDone` se dispare por primera vez. |
| `name_to_id` global resuelve duplicados al archivo equivocado | `build_graph.py` original resuelve todas las referencias contra un map global. Si un nombre existe en dos archivos (p. ej. `edges`, `nodes` del Record `Graph` en StaticSystem), las referencias del segundo archivo apuntan al primero y se crean aristas cross-file espurias. Rompe `transitiveFileDeps`. | blocking | `src/buildGraph.ts` mantiene `localNameToId: Map<file, Map<name, id>>` y resuelve local-primero. |
| `importJson` con conexión abierta | napi-rs no expone `Connection.close()`. Asignar `connection = undefined` no garantiza cierre del handle. Si el archivo está locked, `importJson` puede fallar silenciosamente. | advisory | En `runBuild`: dropear `connection`, `fs.rmSync(gdbPath)`, después `importJson`, después `open` de nuevo. |

<decisions_made>

- **frogql via napi-rs como módulo nativo Node**. Elimina el sidecar Python del plan original. Un proceso, sin HTTP.
- **Sin Vite ni bundler**. `media/webview.html` se lee con `fs.readFileSync` y se inyecta con nonce CSP. vis-network desde unpkg.
- **Resolución local-primero en `buildGraph.ts`**. Necesario para no crear aristas cross-file espurias por nombres duplicados.
- **Cursor scope deriva imports del grafo**. Cualquier arista cross-file implica un import. Subestima cuando un archivo importa otro sin usar nada, pero es raro. Más simple que parsear `Require Import`.
- **Layout layered (Sugiyama simple) dentro de cada archivo** para el modo islands. Rank por longest-path en out-edges intra-archivo, ciclos cortados como rank 0.
- **`groupMode` default = `off`**. El usuario explícitamente prefiere barnesHut natural al abrir; `color + islands` es opt-in.
- **`ready=false` guard en `applyFilters`**. Sin esto, mensajes asincrónicos durante la stabilization inicial corrompen el layout.
- **`graph.json` se borra después del `importJson` exitoso**. Si falla, queda para inspección.
- **frogql 0.2.2 desde npm latest**. El usuario anunció 0.2.3 pero el registry no propagó. 0.2.2 ya tiene `edge.props` que es lo crítico.
</decisions_made>

## Critical Anti-Patterns (do NOT repeat these)

- **No usar `network.moveNode` sobre nodos ocultos** → escribir a `positionCache` y dejar que `applyFilters` los posicione vía `setData`.
- **No llamar `applyFilters` durante la primera stabilization** → el flag `ready` lo previene.
- **No resolver identificadores solo contra el map global** → local-first en `buildGraph.ts`.
- **No usar voseo ni argentinismos en respuestas** → español neutro / castellano.
- **No olvidar `fs.rmSync(gdbPath)` antes de `importJson`** → napi-rs no cierra el handle determinísticamente.
